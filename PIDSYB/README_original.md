# FPGA_Pendulum — 高云 J280 旋转倒立摆控制工程

本工程基于 **J280 Interface_test 例程** 的外设驱动，移植 **WHEELTEC IP570 旋转倒立摆 STM32 源码** 的控制算法，实现：

- 手动辅助起摆
- 自动起摆（能量泵）
- 保持摆杆直立 + 摆臂位置控制 / 转圈

目标器件：**GW2A-LV55PG484C8/I7（GW2A-55C）**，系统时钟 **50MHz**。

## 2. 系统工作流程

### 2.1 数据流

```
                 ┌─────────────────────────────────────────────┐
 3PA1030 ──10bit──► adc.v ──12bit angle──┐                     │
  WDD35D4                                 │                     │
                                          ▼                     │
 编码器 A/B ──► encoder.v ──16bit enc──► pendulum_ctrl.v        │
                                          │                     │
                                          ├── pwm_cmd ──► motor_drive.v ──► TB6612 ──► 电机
                                          │                     │
                                          ├── state/led ──► LED │
                                          └── angle/enc/pwm ──► uart_status.v ──► UART
```

控制周期：

| 周期 | 内容 |
|---|---|
| **5ms** | 角度环 PD、起摆状态机、PWM 输出 |
| **25ms** | 位置环 PD（对应 STM32 的 `Position_Target>4`） |
| **20ms** | 串口状态上报 |

### 2.2 控制律（与 IP570 `control.c` 对应）

**角度环 `Balance()` —— PD（禁止加 I）：**

```
ang_err  = (angle - angle_mid) * ANGLE_INV
ang_d5   = ang_err - ang_err_5ms_ago              // 5ms 差分（必须，见下）
k        = |ang_err| < ANGLE_DZ ? 2^-ANGLE_DZ_SHIFT : 1   // 平衡点附近小增益区
bal_pwm  = -k * (BAL_KP * ang_err + BAL_KD * ang_d5)
```

> D 项必须用 **5ms 差分**。IP570 的 `Balance()` 跑在 TIM1 的 5ms 中断里；若放到 25ms 里算，
> 同样角度变化率会得到 5 倍大的数值（等效 `KD = 140×5`），平衡点附近必然剧烈抖动。

**位置环 `Position()` —— PID：**

```
pos_err  = (enc - 10000) - pos_target
pos_filt = pos_filt - pos_filt/8 + pos_err/8       // 一阶低通 1/8（STM32 版是 1/5）
pos_vel  = pos_filt - pos_filt_prev
pos_int += POS_KI * pos_filt / 2^POS_I_SHIFT       // 抗饱和门控，见 8.1
pos_pwm  = clamp(POS_KP * pos_filt + POS_KD * pos_vel + pos_int, ±PWM_MAX/2)
```

**总输出：**

```
pwm_cmd = clamp(bal_pwm - pos_pwm, ±PWM_MAX)
```

### 2.3 状态机

```
            ┌──────────┐  SW1 启动，手动模式且角度在 ±500 内
            │  S_IDLE  │──────────────────────────────────────┐
            └──────────┘                                      ▼
                 ▲                                       ┌───────────┐
                 │ SW1 停止 / 超角 / 堵转 / 超时          │ S_BALANCE │
                 │                                       │ 角度PD+位置PD │
                 │                                       └───────────┘
                 │                                             ▲
            ┌────┴─────┐   SW1 启动，自动模式                  │ 连续 10 次进入
            │  S_SWING │───────────────────────────────────────┘ 捕获窗口
            │ 能量泵起摆 │
            └──────────┘
```

- **手动辅助起摆**：把摆杆扶到竖直附近，按 SW1 → 记录当前编码器为目标 → 角度环 + 位置环保持。
- **自动起摆**：按 SW1 → 进入 `S_SWING`，按能量泵律驱动摆臂：
  `u = -sign(角速度 × cos(角度误差))`；当连续 10 次满足 `|角度误差| < 350` 且 `|角速度| < 150` 时切换到 `S_BALANCE`。15s 未成功则停机报警。
- **保持直立转圈**：在 `S_BALANCE` 下按 SW3/SW4，`pos_cmd` 每次 ±2080（2 圈），`pos_target` 每 5ms 移动 1 个计数（约 10.4s 转 2 圈），角度环同时保持摆杆直立。

## 4. 按键 / 拨码 / LED

| 操作 | 功能 |
|---|---|
| **SW1** | 停止时：起摆；起摆中：取消；平衡时：**确认执行所选模式**（模式 5 即为摇杆生效） |
| **SW2** | 平衡时：**轮换模式** 0→1→…→5→0（模式运行中按则是停模式，回到纯稳摆） |
| **SW3** | 模式 0（纯稳摆）：目标偏移 **+30°**；模式 1~3：曲线**幅度 +**；**模式 4：拍幅 +10°**；模式 5：无效 |
| **SW4** | 模式 0（纯稳摆）：目标偏移 **−30°**；模式 1~3：曲线**幅度 −**；**模式 4：拍幅 −10°**；模式 5：无效 |
| **SW5** | 复位 |
| **B3_SW1** | 手动标定角度零点（按住即承认当前角度为平衡点） |
| **B3_SW2 拨到 ON（低）** | 编码器方向取反 |

| LED | 含义 |
|---|---|
| LED1~LED3 | 模式号 + 1 的二进制：0 纯稳摆=001，1 正弦=010，2 三角=011，3 线性=100，4 四四拍=101，**5 摇杆=111（全亮）**；慢闪 = 未确认，常亮 = 正在执行 |
| LED4 | 错误闪烁（次数 = err_code） |

### 4.0 摇杆（手轮）模式 —— 移植自 `FPGA_PID_Pendulum`

**操作**：起摆进平衡 → SW2 轮换到 LED 全亮（模式 5）→ 按 SW1 确认 → 转动手轮（XH2 电机轴），摆臂 1:1 跟随 → 再按 SW2 退出（回到纯稳摆，摆臂停在原地）。

**网页操作**（`tools/pos_console.html`）：起摆进 BALANCE 后，点侧栏的「🖐 手轮模式（摇杆）」按钮即可
预选模式 5 并自动确认（`0x1F←5` + `0x10←4`）；再点一次退出发出 `0x10←5` + `0x1F←0`。
按钮文字与「运行状态 → 手轮模式」徽标会按回传的 bit5/bit4 自动切换（跟随手轮 / 已选中·待确认 / 关闭），
「位置环 · 摆臂」卡片新增「手轮编码器（XH2）」实时读数。
⚠ 手轮模式运行中，固件每 5ms 重写 `pos_target`，网页的**拖动/滚轮/±30°/运动曲线**都会被拦截，需先退出手轮模式。

**原理**（与 PID 工程同一套算法）：

```
wheel_pos ← wheel_pos + 手轮增量        // 死区 WHEEL_DEADBAND 过滤静止抖动
给定      ← 每 5ms 最多靠近 wheel_pos WHEEL_RAMP_STEP   // 速度上限 ≈138°/s
给定      不得超前实际位置 WHEEL_LAG_MAX               // 防止位置环饱和、角度环被架空
```

手轮可以转得很快，摆臂受「摆杆必须保持直立」的限制只能慢慢跟；手轮停下后给定继续追上，**最终位置与手轮完全一致**（只是滞后）。

| 参数 | 默认 | 作用 | 调整方向 |
|---|---|---|---|
| `WHEEL_RAMP_STEP` | 2 | 跟随速度上限 counts/5ms（≈138°/s） | 不跟手→3；转快就倒→1 |
| `WHEEL_LAG_MAX` | 150 | 给定允许超前实际位置（≈52°） | 转快就倒→100 |
| `WHEEL_POS_MAX` | 20000 | 目标限幅（±19 圈） | — |
| `WHEEL_DEADBAND` | 2 | 手轮增量死区 | 静止时蠕动→4 |
| `WHEEL_INV` | 1 | 手轮方向取反 | 转向相反→0 |

> 串口 `0x1F` 写 5 也可预选摇杆模式（仍需按 SW1 确认）。
> ⚠ 摇杆模式要求 `top.v` 的 `MOTOR_SEL=1`（B 通道 = 摆臂）与 `USE_ENC2=0`（enc1 = 摆臂），手轮接 XH2。

### 4.0.1 四四拍（4/4）运动曲线 —— 左 左 右 右 / 强 弱 次强 弱

4/4 拍每周期分 4 拍（周期默认 4 s → **每拍 1 s**），每拍是一个 **0 → 峰值 → 0 的半正弦鼓包**，拍与拍之间回零（即“出去再回来”）。

| 拍 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 强弱 | **强** | 弱 | **次强** | 弱 |
| 幅度比 | 1.00 | 0.40 | 0.70 | 0.40 |
| 方向 | 左 | 左 | 右 | 右 |

实际轨迹（`BEAT_AMP = 44` ≈ 15.2°，周期 4 s；实测峰值 14.9 / 5.5 / 10.0 / 5.5°）：

```
角度
 +14.9° ┐        
       │  ╱╲          
   +5.5°│ ╱  ╲   ╱╲  
       0└─╯────╲─╯─╲────╱╲────╲──→ t
                 ╲   ╲ ╱  ╲  ╱
                  ╲   ╲╱    ╲╱
      -10.0°      ╲╱        ╲╱
   ↓ 第1拍(左强) 第2拍(左弱) 第3拍(右次强) 第4拍(右弱)   各 1s
```

（图示为示意：每拍都是「出去 → 回零」，四拍之间没有停留。）

**幅度独立可调**：`BEAT_AMP`（串口 `0x20`，单位编码器计数，1 圈 = 1040）

- 板上模式 4 下按 **SW3/SW4**：±10°（`BEAT_STEP = 29`），范围 0~520 计数（0~180°）
- 串口/网页：写 `0x20`；网页侧栏「🎵 四四拍（左 左 右 右）」按钮下的「拍幅」输入框
- 与模式 1~3 的 `MOVE_AMP`（`0x1D`）**互不影响**

> ⚠ 位置目标仍受 `RAMP_STEP`（1 计数/5ms ≈ 69°/s）限速。周期 4 s（每拍 1 s）时，
> 拍幅超过约 **64 计数（≈22°）** 峰值速度就会撞上限、波形被削顶；
> 想大幅度就同时加大 `MOVE_PERIOD`（`0x1E`）。

**网页操作**：起摆进入 BALANCE → 点「🎵 四四拍」= `0x20←拍幅` + `0x1F←4` + `0x10←4`（arm）；
再点一次 = `0x10←5` + `0x1F←0` 退出。状态由遥测回读显示在「运行状态 → 运动模式」。

### 4.1 MP34DT01 数字麦克风 + 单频 DFT 幅值检测

| 项目 | 值 |
|---|---|
| 供电 | 3.3 V（与 FPGA 板同一路 3.3 V，必须共地） |
| 时钟 | 3.125 MHz（50 MHz ÷ 16），FPGA 输出 |
| 抽取 | 200 → **15.625 kSPS**，3 阶 CIC 滤波 |
| 频谱分析 | **512 点单频 DFT**（正交解调），32.8 ms/块，主瓣宽 30.5 Hz |
| 频率分辨率 | **0.24 Hz**（相位字 16 bit） |
| 频率范围 | 1 Hz ~ 7800 Hz（Nyquist） |
| 幅值量程 | 满幅单音 ≈ **31000** |
| 目标频率 | 串口 `0x18` MIC_FREQ（默认 1000 Hz） |
| 点亮阈值 | 串口 `0x19` MIC_TH（默认 500） |
| 保持时间 | 串口 `0x1A` MIC_HOLD，单位 5 ms（默认 20 = 100 ms） |
| 上电 | 前 2.1 s 直流收敛期，LED3 强制熄灭 |

**算法说明**：本任务只要「某一个频率的幅值」，也就是 DFT 的一条谱线，
用正交解调（Goertzel / 锁相放大器）实现，数学上完全等价：

$$X(f_0)=\sum_{n=0}^{N-1} x[n]\,e^{-j2\pi f_0 n/f_s}=I+jQ,\qquad |X(f_0)|=\sqrt{I^2+Q^2}$$

换频率只需改 NCO 相位字，不需要重算任何系数，代价只有 2 个乘法器
（相比 512 点完整 FFT 的约 3000 LUT）。

`|X|` 用 `max + 0.375·min` 免开方近似（误差 0 ~ −3%），足够做阈值判断。

接线（信号名对应）：

| 麦克风 | FPGA | 说明 |
|---|---|---|
| VDD | 3.3 V | 就近放 100 nF + 1 µF 去耦 |
| GND | GND | 必须与 FPGA 板共地 |
| CLK | `mic_clk`（默认 V16） | 3.125 MHz |
| DOUT | `mic_data`（默认 U16） | PDM 数据 |
| LR / SELECT | GND | 左声道：下降沿更新数据 |

> ⚠ `.cst` 里 V16/U16 是 GW2A-55 PG484 封装中本工程未使用的两只脚，**必须按实际板子的排针确认**后再烧录。
>
> 正弦查找表在 `src/sin256.vh`（脚本生成，256 项，幅值 ±127），
> 由 `mic_fft.v` 用 `` `include `` 引入。该文件**不要**加进 `.gprj` 的 FileList，
> 否则 Gowin 会当成独立源文件解析而报语法错。

**上位机实时波形**（`tools/pos_console.html` 左栏最下方「麦克风音频波形（时域）」）：

- 固件把麦克风 15.625 kSPS 的**时域交流采样**（已去直流）÷8 后，每帧带 39 点上传；
  网页按「时间窗」拼成连续波形，**真正画的是音频信号幅度**（不是单频幅值）
- 纵轴对称自动缩放（按窗口内峰值向上取整到 1/2/5×10ⁿ）；样点多于像素时按像素取 min/max，压缩也不丢峰
- 表头显示 **DFT 幅值（micLvl）/ 窗口峰值 / 量程**；「清空」一起清，「导出 CSV」仍导出角度/位置/PWM/micLvl
- 采样率 1953 Hz（Nyquist ≈ 976 Hz）：能看清语音包络与基频周期、1 kHz 测试音；
  若需要更高保真（3906 Hz），按 `uart_status.v` 头部注释把 `AUD_DEC` 改 4、帧长改 180，
  并同步改网页的 `AUD_FS / AUD_N / FRAME_LEN`（代价：UART 占空比 44%→78%）
- ⚠ 暖机前 2.1 s 输出 0；这不是完整频谱，如需频谱请看前面「单频 DFT」说明

## 5. 串口协议（115200 8N1，每 20ms 一帧）

### 5.1 上报帧（设备 → 上位机，24 字节）

| 字节 | 内容 |
|---|---|
| 0–1 | `0xAA 0x55` |
| 2–3 | 角度（控制器实际采信的 α-β 滤波值，12-bit） |
| 4–5 | 编码器 1（XH1） |
| 6–7 | 编码器 2（XH2，摇杆模式下就是**手轮**） |
| 8–9 | 总 PWM（有符号，大端） |
| 10 | **低 4 位 = 状态机**（0=IDLE 1=SWING 2=BALANCE）；<br>**bit5 = 手轮模式选中**（MOVE_MODE==5）；<br>**bit4 = 模式已确认**（arm） |
| 11–12 | 原始 ADC 角度（未滤波，诊断用）；**字节 11 高 4 位 = 当前预选模式号 0~5**（低 4 位仍是角度高位） |
| 13–14 | 位置环目标 `pos_target`（有符号） |
| 15–16 | 位置环输出 `pos_pwm`（有符号） |
| 17–18 | 麦克风单频 DFT 幅值 |
| 19–20 | α-β 速度估计（有符号，计数/5ms） |
| **21–98** | **麦克风音频时域采样 39 点**（16-bit 有符号大端，每点 2 字节）：<br>15.625 kSPS ÷ 8 = **1953.125 Hz**，每帧「最近 39 点」≈ 20 ms 音频 |
| 99 | 校验：字节 2~98 的异或和 |
| 100–101 | `0x0D 0x0A` |

> 旧上位机若只用 `byte10 & 0x0F` 取状态、`byte11 & 0x0F` 取角度高位，行为不变；
> 但**帧长已从 24 字节变为 102 字节**，按固定长度解析的旧工具（如 `tools/serial_plot.html`，
> 它本来就停在 16 字节版）需要同步改 `FRAME_LEN` / 校验索引 / 帧尾索引。

### 5.2 下发帧（上位机 → 设备，9 字节）

`AA 55 01 | addr | dataH | dataL | chk | 0D 0A`，`chk = 0x01 ^ addr ^ dataH ^ dataL`

| 地址 | 功能 |
|---|---|
| 0x01~0x1F | 各类运行时可调参数（见 §8.0.0） |
| **0x10 = CMD** | **1**=启动/起摆　**2**=停止　**3**=软复位<br>**4**=**确认执行当前模式（arm，等价板上 SW1）**<br>**5**=**取消当前模式（disarm，等价平衡中按 SW2）** |

> 网页 `tools/pos_console.html` 的「🖐 手轮模式（摇杆）」按钮 = `0x1F←5` + `0x10←4`，
> 退出 = `0x10←5` + `0x1F←0`；模式状态由上报帧 byte10 的 bit5/bit4 回读。

### 5.3 上位机页面（`tools/`）

#### 5.3.1 摆臂方向（符号）约定 —— 改之前先读

**显示正向 = 编码器计数减小**，两套机构都是这个方向，网页里统一成：

```
摆臂显示角(°) = SIGN_ARM × (编码器零点 − 编码器计数) × 360 / CPR
拖动/±30°/回零 → 目标计数 = −角度 × CPR / 360 / SIGN_ARM   （FPGA 的 0x0F 是相对计数）
```

依据（三个地方互相印证，别只改一处）：

| 出处 | 公式 |
|---|---|
| STM32 原版 `web/monitor.html` | `encDeg = (zero − encRaw) × 360 / cpr` |
| 本页 `pos_console.html` | `armDeg = SIGN_ARM × (enc − zero) × 360 / cpr`，其中 **SIGN_ARM = −1**（文件内注释：「实测两路都需要取反」/「显示正向 = 计数减小」） |
| `monitor_pidsyb.html` | `posDegOfEnc()` + `degToCount()`，对两套协议都用上式 |

⚠️ 历史坑：`monitor_pidsyb.html` 早期版本在 **FPGA 分支**里写成了 `+(enc − zero)`（STM32 分支是对的），
于是动画和鼠标同向、而实物摆臂反向（一个逆时针一个顺时针），固件并不需要改。
若哪天真换了电机接线导致又反了，勾面板上的**「摆臂反向」**即可（它同时翻转显示和拖动换算，不会只翻一半）。
拖动时的屏幕角度还做了 `unwrapDeg()`，跨 ±180° 时目标不会一下跳一整圈。

**摆杆（角位移传感器）方向**：`摆杆角 = SIGN_PEND × (ADC − 零点) × 系数`，
本机电位器/ADC 的方向与摆臂相反，所以网页默认 **`SIGN_PEND = −1`**（面板上「摆杆反向」因此默认是勾中的）。
摆杆角度只用于显示、不参与任何下发，勾错只会看反，不会动。

#### 5.3.2 「一按就倒下」：点动/拖动必须限速下发

结论：**不是没写速度上限，而是唯一的限速点太快，而且上位机没法让它变慢。**

| | 位置环速度上限 | 说明 |
|---|---|---|
| STM32 固件 | `MOVE_RATE_MAX = 6 counts/5ms` ≈ **415 °/s** | 所有模式共用这一处限速；另有 `POSV` 指令想改速率，但 `Pos_Step` 只被赋值、**没接进限速器**（死变量），所以上位机改不动 |
| FPGA 固件 | `POS_SLEW_MAX = 250 PWM/tick` | 限的是位置环**输出**斜率，等于给了一次「软启动」，所以同样的阶跃在 FPGA 上不摔 |

415 °/s 意味着 0→全速只要一拍，角加速度量级 10³ °/s² —— 摆杆必须前倾 30° 以上才能提供这个加速度，
于是 `TILT_ABORT`（350 counts ≈ 30°）立刻把 `Pos_Follow` 清掉，摆杆直接倒。

**上位机做法**（不动固件）：`monitor_pidsyb.html` 里加了斜坡引擎——
「点动限速」滑块（°/s），每 40 ms 下发一个小增量，带 0.4 s 加减速段和刹停速度限制：

```
vmax = rate(°/s) × CPR / 360                 (counts/s)
acc  = vmax / 0.4                            (counts/s²)
每拍  v = min(vmax, √(2·acc·剩余距离), v + acc·40ms)
      target += v · 40ms
```

默认值 **STM32 50 °/s、FPGA 150 °/s**（按协议分别记忆在 `pend_set_<proto>`）。
50 °/s 时实测：移 30° 用 0.92 s，单片最大 6 counts/40ms = **0.75 counts/5ms**，
远低于固件的 6 counts/5ms 限速 → 固件能精确跟随，不会饱和。丢包/无遥测时退化为直接下发并提示。

#### 5.3.3 STM32 一点「4/4 拍 / 3/4 拍」就倒 —— 固件的节拍是"方波"

`STM32_Pendulum/BALANCE/CONTROL/control.c`（5 ms 平衡分支）：

```c
if(beat_mode == 1) tgt = beat_start + ((beat_idx & 1) ? -Beat_Amp : Beat_Amp);
else               tgt = beat_start + ((beat_idx == 0) ? Beat_Amp : -Beat_Amp);
...
dv = tgt - Position_Zero;
if(dv >  MOVE_RATE_MAX) dv =  MOVE_RATE_MAX;     // 6 counts/5 ms ≈ 415 °/s
```

问题在于：**每拍目标直接从 `+A` 跳到 `−A`（阶跃 2A counts），中间没有任何波形整形**，
只靠 415 °/s 的硬限速去追。代入默认 `Beat_Amp = 100`：

- 阶跃 = 200 counts = **69°**，按 415 °/s 走完约 0.17 s；
- 相当于 5 ms 内把摆臂速度从 0 拉到 415 °/s，摆杆要靠倾斜提供 **10 g 以上**的切向加速度 —— 不可能；
- 结果：位置环输出饱和、摆臂被甩 69°、摆杆倒下，随后 `TILT_ABORT`（350 counts ≈ 30°）把 `beat_mode` 清掉。

对比 FPGA 的四四拍（`motion_gen.v` 模式 4）：每拍是**半正弦鼓包**（`beat_amp × 比例 × sin`），
速度连续、加速度平滑，再加上 `POS_SLEW_MAX` 限输出斜率，所以同样幅值不摔。

**规避（不用改固件）**：把「运动幅度」降到 **≤ 40 counts**（台阶 ≤ 28°、每拍摆幅 ±14°）再点节拍；
上位机点节拍前会先下发 `BAMP`/`BTICK`（保证面板值就是实际生效值），台阶 > 40° 时直接告警。
**根治**：把固件节拍改成半正弦鼓包（照抄 FPGA 的形状），或在固件里给节拍目标加加速度限制。

**⚠ “按节拍没动作”不一定是上位机问题**：`BEAT n` 在固件里需要 `Flag_Stop==0 && hand_start==1 && auto_start==0`，
否则只回 `#ERR NOTREADY` 什么也不做 —— 典型场景是“节拍把摆杆甩倒之后没重新起摆”。
上位机现在会：① 把 `#ERR` 翻译成中文原因（**空原因 = 固件不认识该命令 → 板子里是旧固件**）；
② 每次启动节拍后 500 ms 校验 `#BEAT` 回读，把固件真实回复写进日志和提示行；
③ 连上串口后 2.2 s 做一次**命令自检**（`GETCAL/GETCFG/GETVCFG/GETBEAT`），缺哪个就直说“板子里烧的很可能是旧版固件”。
另外 STM32 固件**不会主动上报停机**，所以页面的 RUN 徽标原本只来自一次性的 `#OK SWING`（会过期）；
现在用过|角度|>40° 持续 400 ms 判定“已倒/停机”并把状态改回 IDLE，避免“页面 RUN、固件 NOTREADY”的矛盾。
音乐节律默认 `节律幅度 40 counts` / `节律周期 4 s`（每拍 1 s），启动后提示行显示“已启动 4/4 拍”。

## 6. 在 Gowin 云源（Gowin EDA）中使用

1. 打开 **Gowin EDA**，`File → Open Project`，选择 `FPGA_Pendulum.gprj`。
2. 确认器件为 `GW2A-LV55PG484C8/I7`。
3. **Synthesize**（综合）→ **Place & Route**（布局布线）。
4. 打开 `Tools → Programmer`，**Operation 必须选 `External Flash Mode`**（见 6.1）。
5. 上电后 LED1 应点亮（若已启动）；串口每 20ms 输出一帧。

> 本工程未包含 `.gprj.user`、`impl/`，首次打开后由 Gowin 自动生成。

### 6.1 ⚠ 掉电不丢失：必须烧到外部配置 Flash

**GW2A-55 是 SRAM 型 FPGA，片内没有配置 Flash**。Gowin Programmer 默认的
`SRAM Program` 只是通过 JTAG 把比特流写进 FPGA 的易失 SRAM，**一断电就没了**。
要让程序上电自动运行，必须把它烧进板载的**外部配置 Flash**，并保证板子的
MODE 引脚在复位时选择 MSPI 启动。

| Operation 下拉项 | 写到哪 | 掉电后 | 说明 |
|---|---|---|---|
| `SRAM Program` | FPGA 内部 SRAM | ❌ 丢失 | 默认选项，只适合调试 |
| **`External Flash Mode`** | 板载 SPI 配置 Flash | ✅ 保留 | **量产/脱机运行用这个** |
| `Embedded Flash Mode` | 片内 Flash | ✅ 保留 | GW2A 系列**不支持**，仅 GW1NSR 等 |

烧写步骤：

1. `Tools → Programmer`，`Operation` 选 **`External Flash Mode`**。
2. `Device` 选 `GW2A-55C` / `GW2A-LV55PG484C8/I7`。
3. 在 `Access Mode` 里选 **External Flash**，并选对 Flash 型号
   （常见 GD25Q16 / GD25Q32 / W25Q32 / MX25L3206…；不知道型号就选同容量通用型号）。
4. 文件列表里 `Add` → `impl/pnr/FPGA_Pendulum.fs`。
5. 点 `Program/Configure`，等待 Erase → Program → Verify 全部通过。
6. **拔掉电源再上电**（复位按钮不会重新从 Flash 加载，只有上电/重新配置才会）。

> `.fs` 是 Gowin 的文本编码比特流（本工程 11,418,409 字符 ≈ 1.43 MB 实际数据），
> 只要 Flash 容量 ≥ 2 MB 就能放下。`.bin` 是等价的二进制版本。

**判断掉电是否真的丢失**：断电重启后看 LED1/LED2 是否还按新逻辑亮。
若烧了 Flash 仍不启动，按下表排查：

| 现象 | 原因 | 处理 |
|---|---|---|
| 烧写时报 `ID check error` | Flash 型号选错 / 板上没有配置 Flash | 核对原理图上的 Flash 丝印 |
| 烧写成功但上电不运行 | MODE 引脚未设为 MSPI | 查手册确认 MODE[2:0] 电平（PG484 上 MODE0=T22/MODE1=U22/MODE2=U21），多数 Gowin 文档中 MSPI 为 `001`，以数据手册为准 |
| 上电后能跑但引脚功能异常 | 配置脚被复用成普通 IO | `Device → Configuration` 里把 MSPI 的 `Reuse as regular IO` 取消 |
| 完全无反应 | 板子本身就是 JTAG-only 教学板 | 只能每次下载，或外挂一颗 SPI Flash 并改 MODE 电阻 |

**一个快速判据**：如果这块板子断电重启后**还能跑出厂的演示程序**，说明板上
一定有配置 Flash 且 MODE 已设好，那你遇到的问题 100% 是「下载方式选了 SRAM」。

## 7. 上机调试步骤（重要）

### 第 1 步：确认方向与零点

1. **不要接电机电源**，先只下载逻辑，观察 LED 与串口。
2. **零点自动校准**：复位后让摆杆自然下垂，约 1.1s 后系统会自动取下垂值并加 2120 得到竖直点（默认 1010+2120=3130），**不需要再按 B3_SW1**。
   - 若上电时摆杆不在下垂位置，系统会使用默认竖直点 3130；
   - B3_SW1 仍保留为可选的手动覆盖：把摆杆扶到竖直，拨 ON 约 1s 再拨回 OFF。
3. 手动转动摆臂，观察串口编码器值：
   - `enc1`（字节 4–5）对应 A 通道，`enc2`（字节 6–7）对应 B 通道；
   - 若方向与预期相反，把 `top.v` 中 `ENC_INV` 设为 `1`，或上电后用 B3_SW2 切换。
4. 若电机转向与预期相反，把对应 `motor_drive` 的 `PWM_INV` 改为 `1`。

### 第 2 步：手动辅助起摆（先保证能站住）

1. 把摆杆手扶到竖直附近（±700 ADC 计数内），按 SW1 启动。  
   （无论 SW2 在手动还是自动，只要摆杆在竖直附近，都会直接进入平衡。）
2. 目前实测已把 `ANGLE_INV` 设为 `1`（角度环取反）。如果电机仍把摆杆往错误方向推（越推越倒），把 `ANGLE_INV` 在 `0/1` 之间切换再试。
3. 观察是否能在小扰动下保持直立：
   - 抖动/啸叫 → 减小 `BAL_KP` 或 `BAL_KD`；
   - 左右缓慢晃 → 增大 `BAL_KD`；
   - 站不住/倒下 → 增大 `BAL_KP`。
4. 能稳定站立后，再调位置环：
   - 位置回中太慢 → 增大 `POS_KP`；
   - 摆臂来回振荡 → 增大 `POS_KD` 或减小 `POS_KP`。

### 第 3 步：保持直立转圈

1. 在平衡状态下按 SW3/SW4，观察摆臂是否**缓慢、平稳**转动且摆杆不倒。
2. 若转不动或摆杆晃动大 → 减小 `POS_KP`、适当增大 `POS_KD`。
3. 一次按键转 2 圈（`POS_STEP=2080`）；想转少一点可改 `POS_STEP`。

### 第 4 步：自动起摆

1. SW2 选择**自动**（LED3 亮）。
2. 把摆杆自然下垂，按 SW1 启动。
3. 观察摆臂是否来回摆动、摆杆幅度逐渐增大：
   - 完全不摆/越摆越小 → 把 `SWING_INV` 在 `0/1` 之间切换（当前为 1）；
   - 摆动但上不去 → 增大 `SWING_GAIN`；
   - 冲过头/抖动 → 减小 `SWING_GAIN` 或增大 `CATCH_WINDOW`。
4. 连续 10 次进入捕获窗口后自动转入平衡；15s 不成功会停机并点亮 LED4。

### 8.0 ⭐ 角度标度变更（2026-10-30）

### 8.1 为什么是「角度 PD + 位置 PID」

旋转倒立摆是**欠驱动**系统（2 自由度、1 个执行器），两个环的分工不同：

| 环 | 类型 | 原因 |
|---|---|---|
| 角度环（5ms） | **PD，禁止加 I** | 摆杆稍偏就必须加速摆臂才能拉回。若角度环带积分，它会把"长期偏一点"当成要消掉的误差持续给摆臂加速，而摆臂加速又改角度 → 摆臂越跑越快 / 低频大摆。机械上摆杆竖直、摆臂不加速时力矩为 0，稳态误差本就该是 0。 |
| 位置环（25ms） | **PID** | 摆臂存在静摩擦、电机死区、机械偏心，纯 PD 会停在 `误差×POS_KP = 摩擦所需力矩` 处，永远回不到零位。这是 I 该解决的问题。 |

**积分项实现（`pendulum_ctrl.v`）**

```
pos_int += POS_KI × pos_filt / 2^POS_I_SHIFT      // 每 25ms 累加一次
pos_pwm  = POS_KP×pos_filt + POS_KD×pos_vel + pos_int
```

三重抗饱和：

1. `pos_int` 钳位到 `±PWM_MAX/4`（≈±1325），积分贡献不超过位置环预算的一半；
2. 只有目标斜坡走完（`pos_target == pos_cmd`）才累加 —— 否则按 SW3/SW4 转圈时的跟踪误差会把积分灌满，转到位后过冲；
3. 误差超过 `POS_I_BAND`（默认 300 计数）时冻结积分 —— 此时 P 已饱和，再积分只会 windup。

**调参**：把 `POS_KI` 设 **0** 就完全退化为原来的纯 PD（综合会整条优化掉）。

- 回不到零位 / 有固定偏差 → `POS_KI` 加倍（32 → 64 → 128）
- 摆臂出现周期好几秒的低频慢摆、像"呼吸" → `POS_KI` 减半
- 若摆杆本身开始晃，说明位置环在跟角度环抢控制权 → 先降 `POS_KI`，再降 `POS_KP`

### 8.2 平衡点附近的小增益区（`ANGLE_DZ` / `ANGLE_DZ_SHIFT`）

#### 要解决的问题

角度环 D 项 `ang_d5 = ang_err - ang_err_prev` 是 **5ms 裸差分，没有任何滤波**，而 ADC 只有 10-bit：

| | 1 LSB（4 计数）抖动产生的 PWM | 占 `PWM_MAX=5300` |
|---|---|---|
| P 项 `50 × 4` | 200 | 3.8% |
| **D 项 `140 × 4`** | **560** | **10.6%** |

**D 项的噪声增益是 P 项的 2.8 倍。** 一个 LSB 的抖动就等效于 0.7°/5ms ≈ 140°/s 的虚假角速度，
直接变成 560 PWM 的力矩冲击 —— 这就是平衡后"一直细颤、电机嗡嗡响"的来源。

叠加两个放大因素：

- ADC 每 **3ms** 更新一次，控制却在 **5ms** 节拍读取，两者不同步会拍频，让 `ang_d5` 呈"0、0、跳变"的阶梯状；
- `BAL_KP=50` 的线性区只有 `5300/50 = 106` 计数（≈9°），`BAL_KD=140` 的线性区只有 38 计数/5ms —— 增益其实开得极大。

#### 实现方式（`pendulum_ctrl.v`）

```verilog
wire in_angle_dz = (ang_err <=  ANGLE_DZ) && (ang_err >= -ANGLE_DZ);

// 在【乘法之前】缩放，等价于把角度环输出右移，
// 但选择器只有 16-bit，不会把 48-bit 移位/选择压到关键路径上
wire signed [15:0] ang_err_g = in_angle_dz ? (ang_err >>> ANGLE_DZ_SHIFT) : ang_err;
wire signed [15:0] ang_d5_g  = in_angle_dz ? (ang_d5  >>> ANGLE_DZ_SHIFT) : ang_d5;

wire signed [31:0] bal_p32 = BAL_KP * ang_err_g;
wire signed [31:0] bal_d32 = BAL_KD * ang_d5_g;
wire signed [47:0] bal_pwm_w = -(bal_p32 + bal_d32);
```

即 `|ang_err| < ANGLE_DZ` 时，整个角度环（P 项和 D 项同时）增益降为 `1/2^ANGLE_DZ_SHIFT`。

当前默认 `ANGLE_DZ=20`、`ANGLE_DZ_SHIFT=1`：

| | 小增益区外 | 小增益区内（±20 计数 ≈ ±1.73°） |
|---|---|---|
| 等效 `BAL_KP` | 50 | 25 |
| 等效 `BAL_KD` | 140 | 70 |
| 线性区 | ±106 计数 | ±212 计数 |

#### 三个设计要点

1. **不是死区。** 区内仍保留 1/2 的恢复力矩，摆杆不会失去支撑。
   角度环**绝对不能加零增益死区** —— 倒立摆开环不稳定（极点位于右半平面），
   死区内摆杆没有任何恢复力，会按指数规律倒下，越过边界时已带角速度，
   结果变成"倒一下、拽一下"的极限环，比细颤更糟。
2. **只作用于 `S_BALANCE`。** `bal_pwm_w` 仅在该状态使用；自动起摆的捕获阶段
   走 `clamp_pwm(-(BAL_KP*ang_err + BAL_KD*ang_d5))`，用满增益 `ang_err` / `ang_d5`，
   不受小增益区影响，避免削弱"抓杆"力度。
3. **`ANGLE_DZ_SHIFT = 0` 完全关闭**，综合会把整条逻辑优化掉，回到原始 PD。

#### 上机现象与对策

小增益区是**增益台阶**而非平滑过渡：在 `|ang_err| = ANGLE_DZ` 边界上输出会跳变
约 `(BAL_KP×ANGLE_DZ + BAL_KD×|Δ|)/2`，默认参数下约 750 PWM（14% 占空比）。

| 现象 | 判断 | 处理 |
|---|---|---|
| 细颤明显减轻，摆杆稳稳站住 | ✅ 成功 | 可试着把 `ANGLE_DZ` 加大到 30~40 进一步压噪 |
| 摆杆在 ±2° 附近**缓慢来回漂**（几秒一个周期） | 区内增益不足 → 极限环 | `ANGLE_DZ_SHIFT` 改 **0**（关闭），或 `ANGLE_DZ` 收到 **10** |
| 摆杆站不住、往一边倒 | 区内恢复力矩不够 | `ANGLE_DZ_SHIFT` 改 **0**，先确认原版能站住 |

> 调参建议：先试默认 `DZ=20 / SHIFT=1`（最保守）。细颤没改善再试 `DZ=30` 或 `SHIFT=2`；
> 出现低频漂移就退回 `SHIFT=0`。

#### 资源与时序代价

| 指标 | 关闭小增益区 | 开启（`DZ=20/SHIFT=1`） |
|---|---|---|
| Fmax | 38.112 MHz | 38.421 MHz |
| LUT/ALU | 1940 | 1975 |
| DSP | 3 | 4（共 20，余量充足） |
| 寄存器 | 596 | 596（无变化） |

> 改为乘法**之前**缩放后时序恢复。若今后要改这段逻辑，务必保持在 16-bit 域内做选择。

### 8.3 α-β 滤波器（角度环 D 项抗噪）

#### 要解决的问题

角度环 D 项原本是 **5ms 裸差分**：

```verilog
ang_d5 = ang_err - ang_err_prev;      // σ ≈ 31 计数/拍
```

ADC 量化 + 机械振动使角度噪声 σ ≈ 22 计数，差分后放大 √2 倍，
再乘 `BAL_KD=180` 得到 **±5567 PWM 的噪声**——已经超过满量程（5175）。
这就是"必须靠 `ANG_D_LPF_SHIFT` 或降低 `BAL_KD` 来压噪、因而牺牲阻尼"的根因。

对位置做低通**解决不了**这个问题：低通会带来相位滞后，把 D 项的 90° 超前吃掉，
变成负阻尼 → 十几 Hz 自激（见 8.0 节的推导）。

#### 解法

α-β 滤波器直接估计**速度**，不需要对位置做差分、也不需要低通：

$$\begin{aligned}
\hat{x}^- &= \hat{x} + \hat{v}\\
r &= z - \hat{x}^-\\
\hat{x} &\leftarrow \hat{x}^- + \alpha r\\
\hat{v} &\leftarrow \hat{v} + \beta r
\end{aligned}$$

它是匀速模型下**卡尔曼滤波的稳态形式**，`α`、`β` 就是收敛后的卡尔曼增益。
关键性质：**对匀速输入零稳态滞后**（已验证：斜坡跟踪误差精确为 0.000 计数）。

#### 接入点

| 信号 | 改动前 | 改动后 |
|---|---|---|
| `angle_f`（P 项 + 遥测） | `angle` 直通 | `u_ab.x_out`（平滑后角度） |
| `ang_d5_filt`（D 项） | `ang_err_f - ang_err_f_prev` | `±u_ab.v_out`（估计速度） |

只作用在 **`S_BALANCE`** 路径。`S_SWING` 仍用原始角度与原始差分——
起摆捕获要的就是实时性，不能被平滑拖慢。

另外把 **ADC 削顶检测**从 `angle_f` 改回原始 `angle`：
削顶是硬件量程端点，若用滤波后的值会晚 5~10 拍才触发。

> 滤波器工作在**原始角度**上，而不是 `ang_err`。
> 因为 `angle_mid` 运行时会变（串口 / B3_SW1），若滤误差量，改零点会凭空
> 产生一个速度尖峰；滤原始角度则零点只影响 P 项，D 项不受影响。

#### ⚠ 时序与节拍（改这里之前务必读）

`alpha_beta` 的输出是**寄存器输出**。如果控制逻辑在同一个 `tick_5ms` 边沿采样，
拿到的是上一拍的滤波值，等于在角度环里凭空多出 **5 ms 纯延迟**，会吃掉 D 项
的相位超前。

**不能**为了消除这个延迟把输出改成组合逻辑 —— 实测 setup slack 直接掉到
**−12 ns / TNS −2425 ns**，因为
「x̂ → 预测加 → 新息减 → α 乘法 → 移位 → 相加 → 取整 → 钳位」
整条链又串进了 `pendulum_ctrl` 已有的两级乘法（小增益区 + KP/KD）。

**正确做法**（已实现）：把控制节拍延后 **1 个时钟**再采样。

```verilog
reg tick_c, tick25_c;
always @(posedge clk or negedge rst_n)
    if(!rst_n) begin tick_c <= 1'b0; tick25_c <= 1'b0; end
    else begin tick_c <= tick_5ms; tick25_c <= tick_25ms; end
```

- `u_ab` 实例仍用**原始** `tick_5ms`
- 主 `always` 块里的参数提交、标定、控制全部改用 `tick_c`
- 位置环两级流水：`tick5_d <= tick_c` / `tick25_d <= tick25_c`

代价从 5 ms 降到 **20 ns**。

> 残余延迟：`ang_err_gr` 这一级流水寄存器（小增益区为拆两级乘法而加，早已存在）
> 会让 α-β 相比原实现再多约 1 个控制周期（5 ms）。这是该流水寄存器的固有开销，
> 与 α-β 无关；32 倍的 D 项降噪远超这 5 ms 的代价。

#### 遥测：如何确认滤波器真的在工作

| 遥测字段 | 含义 |
|---|---|
| `angle` | **α-β 滤波后**的角度（控制实际采信值）—— **已改为始终发送，不再按状态切换** |
| `rawAngle` | 原始 ADC 值，用于对比 |
| `abV` | α-β 速度估计（计数/5 ms，已按 `ANGLE_INV` 取反） |

> **历史坑**：最初 `angle_used_dbg` 只在 `S_BALANCE` 才发滤波值，其余状态发原始值。
> 而现场看读数时几乎总是停机状态，于是上位机看到的永远是原始角度，
> 看起来「滤波器没接进去」。现在固定发控制实际使用的值。

网页控制台「角度环 · 摆杆」卡片新增两行：

```
原始 / 滤波    3224 / 3227  Δ+3
α-β 速度       0  cnt/拍
```

并把窗口内 100 点的标准差 σ 直接显示在「误差」后面，可用来验证降噪效果：
滤波前后 σ 应约为 **22 → 8.6**。

#### 实测数据（Python 逐位复现定点逻辑，σ=22 计数输入噪声）

| α (Q8) | β (Q8) | 位置 σ | 压缩 | 速度 σ | 压缩 |
|---|---|---|---|---|---|
| 13 (0.051) | 1 (0.004) | 5.46 | 4.0× | — | β 太小，v 基本冻结 |
| 26 (0.102) | 1 (0.004) | 5.79 | 3.8× | — | 同上 |
| **51 (0.199)** | **6 (0.023)** | **8.63** | **2.6×** | **0.90** | **34.3×** |
| 77 (0.301) | 14 (0.055) | 10.72 | 2.1× | 1.72 | 18.0× |
| 102 (0.398) | 25 (0.098) | 12.41 | 1.8× | 2.74 | 11.3× |
| 153 (0.598) | 65 (0.254) | 15.51 | 1.4× | 6.35 | 4.9× |
| 205 (0.801) | 137 (0.535) | 18.47 | 1.2× | 13.53 | 2.3× |

裸差分速度噪声 σ = 30.88。**默认 α=51 / β=6 时 D 项噪声降低 34 倍**，
P 项噪声降低 2.6 倍。定点与浮点实现的最大偏差 0.5 计数（仅输出取整误差）。

#### 调参

| 串口地址 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `0x1B` | `AB_ALPHA` | 51 | α（Q8），51 = 0.199 |
| `0x1C` | `AB_BETA` | 6 | β（Q8），6 = 0.0234 |

约定 `β = α²/(2−α)`（Benedict–Bordner，双极点重合）。Q8 形式：

$$\beta_{Q8}=\mathrm{round}\!\left(\frac{\alpha_{Q8}^2}{512-\alpha_{Q8}}\right)$$

网页控制台有「按 α 算 β」按钮自动换算。

| 现象 | 判断 | 处理 |
|---|---|---|
| 细颤明显减轻 | ✅ 成功 | **可以把 `BAL_KD` 从 180 往上提**（现在噪声不再是瓶颈） |
| 摆杆反应迟钝、倒向一边 | α 太小，跟踪不上真实倾倒 | α 提到 77~102 |
| 仍有高频细颤 | α 仍偏大 | α 降到 26~51 |
| 摆杆低频来回晃 | β 太大，速度环自激 | β 降一半，或按公式重算 |

> **建议的下一步**：α-β 上线后，先保持 `BAL_KD=180` 确认能站住，
> 再逐步把 `BAL_KD` 提到 300 / 400——之前受噪声限制不敢加的阻尼现在可以加了。

#### `AB_EN` 开关

`pendulum_ctrl.v` 的 `AB_EN` 参数（编译期）：

- `AB_EN=1`（默认）：启用 α-β
- `AB_EN=0`：完全恢复旧的裸差分实现，用于 A/B 对比

做成编译期常量而不是运行时开关，是为了避免在角度关键路径上多插一级 2:1 选择器。

#### 资源与时序代价

| 指标 | 加 α-β 前 | 加 α-β 后（组合输出，×不可用） | 最终版（寄存器输出 + tick_c） |
|---|---|---|---|
| LUT | 4566 | 4949 | 5000 |
| 寄存器 | 2085 | 2182 | 2212 |
| DSP | 9.5 | 11.5 | 11.5 |
| Setup TNS | −1390 ns | **−2425 ns（恶化）** | −1494 ns |
| `u_ab` 在关键路径 | — | **是（−12 ns）** | **否（完全不在报告里）** |

> 坐标变换 `±(angle - mid)` 使 `d(ang_err)/dt = ±d(angle)/dt`（`mid` 为常数），
> 所以 `v_out` 需按 `ANGLE_INV` 取反后才能当作 D 项使用——代码里由 `ab_v_signed` 完成。
>
> TNS 从 −1390 涨到 −1494 是布局被新逻辑挤动后 `u_ctrl` 历史遗留违例的抖动，
> 与 α-β 无关（`u_ab` 不出现在时序报告的任何路径上）。

## 10. 已知限制与注意事项

1. **本工程未在 Gowin EDA 中实际编译过**：代码按可综合 Verilog-2001 编写，首次综合时请留意工具警告（位宽、未使用信号等）。
2. **角度零点自动校准**：复位后 1s 内让摆杆自然下垂，系统会自动取下垂值 + 2120 作为竖直点；若上电时不在下垂位置，则用默认 3130。B3_SW1 仅作可选手动覆盖。
3. **方向符号**（电机/编码器/角度）必须实测确认：手动起摆时若电机把摆杆往错误方向推，把 `ANGLE_INV` 设为 1；编码器/位置环方向不对则设 `ENC_INV=1` 或用 B3_SW2。建议先不接电机电源调试。
4. **自动起摆能量泵的方向**依赖机械安装，若越摆越小请把 `SWING_INV` 取反。
5. `ADC` 的 `adc_stby_n` 引脚沿用原 `Interface_test` 工程的自动分配位置（T6 / 1.8V）；若原理图不同，请修改 `FPGA_Pendulum.cst`。
6. LED 引脚在 BANK_3（1.5V）；若实际不亮，可把 `FPGA_Pendulum.cst` 中 LED 的 `IO_TYPE`/`BANK_VCCIO` 改为 `LVCMOS33`/`3.3`。
7. 上电/复位后请让摆杆自然下垂，等约 1.1s 自动校准完成后再启动；运行中不要拨动 B3_SW1。
8. 调试时建议先用 `PWM_MAX` 较小的值（如 3000）限制力矩，确认方向后再放开。
